Agent 开发进阶：选模型、提速度与 Workflow 的边界

作者：汤文  日期：2026-09-13  阅读时长：约 8 分钟

这一篇解决三个工程上很实际的问题：模型怎么选、响应速度怎么提、什么时候该用 workflow 而不是 agent。

如何选模型

「没有最好的模型，只有最适合的模型。」先看两类模型的定位。

旗舰模型（Flagship / Pro / Opus / o3 / GPT-5 / Claude Opus / Gemini Pro）：

  • 特点：参数规模最大（或激活参数多）、推理深度最强、复杂任务（如深度逻辑、长链思考、编程 Agent、多步规划）表现最佳。
  • 优势：高准确率、强 reasoning（尤其是 o-series / reasoning 模式）、复杂问题解决能力强。
  • 劣势：响应慢（尤其是思考型模型）、成本高、并发限流可能较严。

蒸馏模型 / 轻量模型（Distilled / Mini / Flash / Haiku）：

  • 特点：通过知识蒸馏（distillation，从旗舰模型生成合成数据训练小模型）或 MoE（混合专家，只激活部分参数）实现「用更少资源接近旗舰性能」。
  • 优势：速度快（低延迟、高吞吐）、成本低（常为旗舰的 1/3~1/10）、适合高并发或实时场景，性能在简单-中等任务上接近旗舰。
  • 劣势：极端复杂推理或边缘案例上可能略逊旗舰（reasoning ceiling 较低）。

如何选择？可根据下面几条场景判断：

  • 任务复杂度（最重要）。
  • 速度与实时性。
  • 成本敏感度：输出 token 通常比输入贵 5-10 倍。
  • 上下文长度与多模态。
  • 部署与数据隐私：需要隐私的，就选开源的。
  • 中文 / 多语言能力。

如何提升 Agent 的响应速度

  • 选择更快的模型，比如 Doubao-Seed-1.6-flash 这类轻量模型。
  • 优化大模型推理流程：KV Cache 缓存优化、Prompt Cache 缓存优化；系统提示词要动态结合（静态的放前面，动态的放后面）；合理设置 max token 与 temperature。
  • 设置语义缓存等方式，让相似问题直接命中缓存结果，减少重复推理。

Workflow 和 Agent 的区别

Agent 是一个可以独立完成某一项任务的系统，核心是自主：大模型主动且动态地执行流程与工具调用，独立地完成某一项任务（有一定风险）。

比如给 Agent 系统一个任务，Agent 会通过状态感知，自动调用各种工具来达成这个目标。而 workflow 只会按照某个流程来完成这个任务。

Workflow 是通过预定义的流程来协调大模型和工具的系统，但它稳定高效。

所以工程上的取舍是：流程确定、要求稳定可控的场景优先用 workflow；任务开放、路径无法预先穷举的场景才交给 agent，并配套护栏与验证机制。
