LLM 原理：Transformer、KV Cache、LoRA 与采样

作者：汤文  日期：2025-07-05  阅读时长：约 12 分钟

这一篇把大模型侧的基础原理过一遍：Transformer 的注意力机制、Decoder-only 架构、KV Cache、LoRA 高效微调、温度采样，以及 Reranker 背后的 Cross-Encoder。

Transformer 的理解

Transformer 最核心的部分是它的多头注意力机制。然而注意力机制并不关心一个句子中 token 的位置，所以在进入多头注意力模块前，需要加入正弦余弦位置编码。

在多头注意力模块中，会对向量矩阵使用全连接层生成对应的 Q、K、V 矩阵。计算 Q 乘以 K 的转置，得到的结果可以表示单词之间的注意力强度；除以根号 d 做缩放，再使用 Softmax 计算每一个单词对于其他单词的 attention 系数，最后和 V 相乘，得到最终的输出 Z，它代表了每个词的「上下文表示」。

后续无非就是残差链接、归一化、全连接层，组成一个 Encoder Blocker，编码器由多个 Encoder Blocker 串连起来。在解码器的 Blocker 中多了一个掩码多头注意力模块，用来防止生成时看到未来位置的 token。

【注】注意力机制是什么：注意力机制就是让模型在处理序列时，自动给重要信息分配更高权重，聚焦关键内容。

【注】对 QKV 怎么理解的：Q、K、V 是通过线性变换得到的三个向量，分别对应：

  • Q（Query）查询：我现在要找什么。
  • K（Key）键：别人有什么内容。
  • V（Value）值：真正要提取的信息。

注意力本质就是：用 Q 去匹配所有 K，得到权重，再对 V 加权求和。加权求和的结果，就是把序列里所有词的信息，按「重要程度」揉在一起，得到当前词的「上下文表示」。

Decoder-only 的理解

Decoder-only 架构只使用 Transformer 的解码器模块堆叠而成，没有编码器部分，像 GPT 系列都是典型的 Decoder-only 模型。

它采用自回归生成方式：生成时逐个输出 token，每预测下一个词时，只能看到当前输入和历史已经生成的 token，通过掩码多头自注意力屏蔽未来位置的信息，保证不会泄露未生成的内容，利用历史上下文不断迭代预测下一个 token，直到生成结束。

相比 Encoder-Decoder 架构，Decoder-only 结构更简洁，天然适配生成式任务，非常适合大语言模型做对话、续写、文本生成。

KV Cache 的理解

在大模型推理过程中，需要将最新 token 的 Q 与所有历史 token 的 K 进行点积运算，再与所有历史 token 的 V 进行点积运算。在这个过程中，如果所有历史 token 的 K 和 V 都要重新计算，就会有许多冗余的计算，大大增加推理的计算量与延迟。

所以引入了 KV Cache：把之前计算过的 K（键）和 V（值）矩阵缓存起来，后续生成新 token 时，无需重新计算所有历史 KV 数据，只需复用缓存的结果，大幅减少重复计算，节省推理时间和资源。

这也是为什么系统提示词要尽量保持静态前缀——稳定的前缀可以让这部分 KV 与计算被复用，从而提升首 token 速度和整体吞吐。

LoRA 的理解

传统模型微调需修改全部参数，参数量大、训练耗时，且易破坏原模型性能。LoRA（低秩适配）是高效微调技术，不改变原模型参数，仅在关键层添加两个低秩矩阵，通过训练这两个小矩阵，就能快速让模型适配新的任务需求，既保证了训练效率，又有效避免了原模型性能受损，实现了效率与性能的双重兼顾。

为什么使用低秩矩阵：之所以选择低秩矩阵，是因为模型参数的变化通常具有低秩特性，低秩矩阵能够以远少于原模型参数的规模，精准捕捉任务适配所需的参数变化，无需修改全部参数就能实现模型微调。

数学原理：冻结原始权重 W，只在每个线性层旁加两个低秩矩阵 A（r×d）和 B（d×r），ΔW=BA，训练参数量从 d×d 降到 2×d×r（r<<d，通常 r=8-64）。

为什么低秩：

  • 权重更新矩阵 ΔW 在微调时天然低秩（研究发现 rank 远小于 d）。
  • 数学上：任何矩阵都可 SVD 分解，保留前 r 个奇异值就能近似原更新，效果接近全参数微调，但显存 / 算力只剩 1/10-1/100。
  • 额外好处：易合并（merge back 到原模型）、多 LoRA 切换快（Adapter）。

SVD（奇异值分解）说明

SVD 可以把任意一个矩阵（比如 LoRA 里的权重更新矩阵 ΔW）拆解成三个部分：ΔW = U × Σ × V^T。

  • U 和 V 是正交矩阵（可以理解为「方向矩阵」），Σ 是对角矩阵，对角线上的数值就是奇异值（按从大到小排列）。
  • 奇异值的大小代表了这个「方向」上的信息强度：前几个大的奇异值包含了矩阵的绝大部分信息，后面的小奇异值几乎是噪声。

低秩近似：既然大部分信息集中在前 r 个奇异值上，我们可以只保留前 r 个奇异值（把后面的都置为 0），得到一个新的矩阵 Σ_r，用 U × Σ_r × V^T 就能近似还原原来的 ΔW。

Temperature 等于 0 会怎么样

设置 Temperature=0 时，许多框架会切换到纯贪心模式，确保输出可重复。

纯贪心模式的做法是：

  • 每次只选择概率最高的那个 token（即 argmax 操作：取 logits 或概率中的最大值）。
  • 直接把这个 token 加入已生成序列，作为下一步的输入。
  • 重复这个过程，直到生成结束符、达到最大长度或其他停止条件。

为什么 Temperature 等于 0，模型的输出依然不确定

浮点加法不满足结合律，是因为有限精度下的舍入；模型计算中顺序不同，是因为 GPU 为了极致性能，使用了依赖 batch size / 并行策略的动态优化 kernel，导致累加树形状变化，最终舍入误差不同。

这些差异虽然很小，但因为 LLM 是自回归生成（一步错、步步错），一个 token 的 logit 翻转（原本第二高的 token 变成最高），后续整个序列就可能完全不同。

Re-ranker 如何工作：Cross-Encoder 简介

为什么 Re-ranker 更准？因为它通常使用一种叫做 Cross-Encoder（交叉编码器）的模型结构。

  • 我们之前用于 Embedding 的，叫 Bi-Encoder（双塔编码器）。它将问题和文档分开编码成向量，再计算相似度。速度快，但无法捕捉两者之间深层的交互信息。
  • 而 Cross-Encoder，则是将问题和文档拼接在一起（[CLS] 问题 [SEP] 文档 [SEP]）后，再输入给一个强大的预训练模型（如 BERT）。这使得模型可以充分地、逐词地比较问题和文档的内部细节，从而给出极其精准的相关性判断。

缺点就是计算量大、速度慢。所以它不适合用于海量文档的初筛，但极其适合对小范围的候选集进行「精加工」。
