PPO 与 GRPO：把大模型当作策略来优化

作者：汤文  日期：2025-08-05  阅读时长：约 12 分钟

有了奖励模型，接下来才是真正棘手的一步：用它去优化语言模型本身。这一篇把文本生成抽象成序列决策过程，讲清楚策略梯度到底在最大化什么、参考模型与 KL 约束为什么必不可少，再对比 PPO 与 GRPO 在优势估计上的不同做法。

强化学习微调：将文本生成视为序列决策过程

在强化学习框架中，一次文本生成可以被完整地映射成一套序列决策的语言。于是语言模型不再只是一个“下一个词预测器”，而是成为一个在状态之间转移、并不断选择动作的策略。

  • 状态（State）：已生成的文本序列，也就是当前的上下文。
  • 动作（Action）：从词表中选择下一个 token，或者生成下一个片段。
  • 策略（Policy）：语言模型本身，参数化为 π_θ，它根据当前状态输出动作的概率分布。
  • 轨迹（Trajectory）：一次完整的文本生成过程，从开始一直到结束符。

将语言模型作为策略进行优化

把语言模型当作策略之后，整个微调任务就可以用强化学习的语言重新描述。我们需要明确两样东西：

  • 策略（Policy）：待微调的模型 π_θ(y|x)，即给定输入 x 时生成响应 y 的概率分布。
  • 奖励函数（Reward）：使用训练好的奖励模型 r_φ(x,y)，为整条输出打分。

我们把语言模型视为策略 π_θ，目标是最大化期望奖励，也就是说，通过微调模型让模型输出的结果有更大概率具有高奖励。为了让这个目标可以计算，损失函数被定义为整个生成序列的加权总得分。

这个公式是在计算整个生成序列的加权总得分，可以拆成三部分理解：

  • [prob of next token]：这是模型原本预测下一个 token 出现的概率，来自大模型的基础训练。
  • [how good token was]：这是这个 token 的奖励值（或质量分），由奖励模型（Reward Model）给出。它反映了这个 token 对生成高质量、符合人类偏好的序列有多大贡献。
  • Σ（求和）：把序列中所有 token 的「概率 × 质量分」加起来，得到整个序列的加权总得分。

对于这个损失函数，需要更新的参数是大语言模型（策略模型）本身的所有参数，比如 Transformer 的注意力层、全连接层权重，这些参数直接决定了 prob of next token，也就是模型生成每个 token 的概率。而 how good token was，即奖励值，是固定的、无梯度的，它只作为“加权系数”引导模型参数更新，本身不会被优化。

所以可以理解为：想让这个损失函数的值变大，这样这个序列的得分越高，也就是奖励越高。换言之，就是让具有高奖励的 token 的概率更高，让负奖励的 token 的概率更低。

高度总结就是：让高奖励的 token 更容易被生成，让低奖励的 token 更不容易被生成，而这一切都是通过调整策略模型的参数来实现的。

如何计算上面的损失函数

先看前半部分，也就是 [prob of next token] 这一项。

第一阶段：给模型输入提示词 x，让模型产生响应 y，再用奖励模型计算奖励 v，得到一条轨迹数据 (x, y, v)。对此重复多次即可获得轨迹数据集。此过程没有梯度更新。

第二阶段：利用轨迹数据集微调主语言模型。模型会在每一批次中进行梯度更新。此时有个问题：优化后的模型在预测 token 时的概率与原本的模型不一样了，这导致第一阶段收集的数据集可能就不合适了。因为第一阶段收集到的轨迹数据 (输入 x、响应 y、价值 v) 是一对，此时 token 的概率与奖励与当前模型不匹配了，并使训练过程不稳定。

所以为了解决这个问题，我们使用参考大语言模型，这个参考模型就是微调之前的主模型，并将 prob of next token 用一个新的量来替代：用当前正在训练的模型预测的概率与参考模型的预测的概率的比值作为 prob of next token。比如当比值大于 1，意味着新模型比参考模型更可能生成该 token。

那么还有个问题：如何得到某个 token 的概率呢？这个很直观，在模型生成序列时就提供了每个 token 的概率，直接获取即可。

再看后半部分，也就是 [how good token was]，即如何判断一个 token 的质量。

在 RLHF（人类反馈强化学习）的流程里，token 的质量不是直接给的，而是通过奖励模型（Reward Model）和序列级奖励反推出来的。

  • 第一步：人类标注与奖励模型训练。我们先让大模型生成多个候选回答，然后让人类标注员对这些回答进行排序，选出最符合人类偏好的那个。用这些排序数据训练一个奖励模型，它的输入是完整的对话（x + y），输出是一个标量奖励值 R(x,y)，代表整个序列的质量。
  • 第二步：把序列奖励拆解为 Token 级奖励。我们想要得到每个 token 的贡献，常用方法是 Token 级奖励归因，比如对比法、梯度归因与蒙特卡洛采样。
  • 对比法：比较“包含这个 token 的序列”和“不包含这个 token 的序列”的奖励差异。
  • 梯度归因：计算奖励函数对每个 token 的梯度，梯度的大小就代表该 token 对最终奖励的贡献度。
  • 蒙特卡洛采样：在生成过程中，动态计算到当前 token 为止的累积奖励期望，作为它的质量分。

除此之外，也可以直接使用整个序列的价值作为每个 token 的价值。这样，我们就能给序列里的每个 token 都分配一个质量分 r_i，来表示它对整个序列奖励的贡献。

上面的方法确实获得了每个 token 的价值，但这可能并不太好，会导致训练过程可能更难收敛，效果也未必好。因为这可能让模型投机取巧，比如只重复高分词，这样也能让整个损失很高。所以为序列中的 token 估计一个基准线很有必要，这个基准线一般可以取所有 token 的平均值。

然后让每个 token 的价值减去这个基准线，得到的数值就是 [how good token was] 的值。这样得到的价值有正有负，集中在 0 的两侧，在强化学习中这被称为 token 的优势（advantage）。奖励减去基准值得到的结果被称为优势（advantage），它表示你的 token 表现得有多好。计算优势的方法还有很多种。

以上就是损失函数的计算，然后就可以进行梯度上升来更新模型了。这里使用梯度上升，是因为我们希望损失函数越来越大的。

整个过程涉及三个模型：奖励模型、需要训练的模型、参考模型。

使用参考大语言模型（LLM_ref）来稳定训练

直接让 LLM_θ 一味追求高奖励，会导致它偏离自然语言太远，可能胡言乱语，或者过度优化到奖励模型的漏洞上。

所以我们要约束 LLM_θ 在每个词上的输出概率不要和 LLM_ref 差太多。做法是比较同一个位置生成某个词的概率在 LLM_θ 和 LLM_ref 下的比值（importance ratio）。

PPO（近端策略优化）

PPO 被用于人类反馈强化学习（RLHF）中，它主要在两个方面对前面的做法做了改进。

第一，在 PPO 中对基准线的计算进行了改进。我们训练另一个模型来计算基准线，这个模型的唯一任务就是预测每个 token 的期望奖励，而不是预测整个序列的奖励。只需要在同一个大模型中加一个新头，让其预测每个 token 的奖励。为了让 token 的奖励更准确更平滑，还设计了优势函数评估器，即 GAE（广义优势估计）。GAE 利用基准线模型将最终奖励反传到更早的 token，因此更早的 token 会因最终结果而获得奖励或惩罚；它会以一定的折扣因子回溯这些先前奖励，折扣因子是个超参数，这个 GAE 算法会让奖励在 token 间平滑分布。

第二，PPO 还对第一部分的概率比值做了优化。有时这个比值会非常大或非常小，导致更新不稳定，PPO 通过截断该比值来解决这个问题，也就是设定上限和下限，当这个比值超过上限或下限时就使用上限或下限来代替这个比值。这样可以防止权重的更新超过设定的阈值。PPO 通过小而稳的步伐防止模型在训练中崩溃，这就是 PPO 的核心思想。

PPO 训练过程总结如下，它整体是一个强化学习（RL）循环：

  • 获取强化学习数据。从参考大语言模型（LLM）中获取完整的轨迹数据，格式为 {输入, 输出}；再为轨迹数据添加奖励，得到格式为 {输入, 输出, 奖励} 的完整轨迹。
  • 在轨迹数据上用强化学习训练主大语言模型（LLM）。先定义近端策略优化（PPO）目标：用优势值来加权下一个 token 的概率。其中要对概率比值添加裁剪（Clipping）操作，以稳定模型更新；同时训练另一个大语言模型，来为优势值计算提供基线估计。然后基于 PPO 目标更新大语言模型，以最大化奖励。
  • 重复步骤 1 和 2 直至训练完成。

PPO 又引入了一个基准线模型，导致更大的计算资源压力，所以 GRPO 就解决了这个问题。

GRPO（组相对策略优化）

GRPO 的核心创新是去掉了单独的基准线估计模型，它改变了基准线的计算方式。GRPO 提出：为什么不直接为单个输入生成多条输出，然后计算它们的实际平均奖励呢？

具体来说，GRPO 通过为同一个输入生成多个不同的输出，并通过奖励模型得到各自的奖励，这些输出作为一组，计算这一组奖励的平均值和标准差。对于组里的每一个输出，计算方式如下：奖励减去平均值再除以标准差。也就是说，用组内的相对表现来替代原本需要单独训练的价值网络所给出的优势估计。

在 GRPO 中只改变了基准线的计算方式，保留了 PPO 中的截断算法。
