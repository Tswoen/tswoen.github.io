Agent 的短期记忆与长期记忆

记忆的划分标准

短期记忆与长期记忆，是从功能定位而非存储介质来定义的。记忆的主体是 Agent，要站在 Agent 的角度来看待：比如用户的历史记录，对于 Agent 来说只对当前会话有用，这是短期记忆；比如系统的外部资料、用户的偏好，这对 Agent 来说每次都要遵守、要时刻记住，所以这是长期记忆。

换句话说，判断标准不是「存在内存还是磁盘」，而是「这份信息在 Agent 的视角下承担什么职责」。

短期记忆

AI Agent 里的「短期记忆」核心是「服务当前会话 / 任务的临时信息」。哪怕物理上存到了磁盘（比如临时缓存文件），只要它的作用是支撑当前上下文连续性、且会被后续新信息「覆盖 / 清除」（比如超出滑动窗口后被丢弃），就属于短期记忆的范畴。

  • 典型内容：本轮对话历史、当前任务的中间结果、工具调用的观察结果。
  • 生命周期：随会话推进被压缩、裁剪或直接丢弃。
  • 关注点：上下文的连续性，以及窗口被撑爆时的压缩策略。

长期记忆

而长期记忆的「持久化」是主动、长期保留的价值信息（比如用户偏好），不是临时缓存的会话记录。

  • 典型内容：用户画像与偏好、领域知识库、沉淀下来的技能与规范文档。
  • 生命周期：跨会话保留，需要定期整理与更新。
  • 关注点：如何写入、如何检索、如何避免错误信息持续沉淀。

两者的关系

短期记忆解决的是「这一轮对话不要断片」，长期记忆解决的是「换个会话它还记得我」。工程上常见的设计是：短期记忆用滑动窗口 + 摘要压缩来维持上下文，长期记忆用检索的方式按需注入，二者配合才能既保证当前任务的连贯性，又保证跨会话的一致体验。
